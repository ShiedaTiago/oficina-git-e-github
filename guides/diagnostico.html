Quando algo sair do esperado

Leia a mensagem. Preserve seu trabalho.

Comece com git status. Copie a mensagem de erro para pedir ajuda, removendo credenciais e dados pessoais. Execute cada passo apenas na pasta do exercício.

“git: command not found” ou “git não é reconhecido”

O terminal não encontrou o programa. No Windows, abra Git Bash pelo menu Iniciar; se acabou de instalar, feche o terminal e abra novamente. No Linux, confira a instalação da sua distribuição no guia de preparação. No Windows, volte à instalação do Git for Windows.

git --version

Sem permissão de instalação, peça ajuda à administração. Não baixe executáveis de sites de correção de erros.

“not a git repository” ou arquivos inesperados

pwd
ls
git status

Confirme que está na cópia de site-da-turma, e não na pasta pessoal, no pacote da apresentação ou em outra cópia do projeto. Use cd ~/oficina-git/site-da-turma se seguiu a preparação.

Se o exercício local ainda não executou git init, esse erro é esperado. Execute a inicialização somente quando o roteiro pedir, dentro da cópia correta. Um repositório obtido com git clone já vem inicializado. Não apague a pasta .git para tentar corrigir um problema.

“Author identity unknown”

Dentro do repositório, consulte a identidade efetiva:

git config user.name
git config user.email

Se estiver vazia, siga a configuração de identidade e tente novamente o commit. O exemplo Ana Exemplo é fictício. Use seu endereço verificado ou o noreply copiado da sua conta. Nome/e-mail não resolvem problemas de login.

Falha de autenticação ou “Repository not found”

  1. Confira internet e abra o repositório no navegador com a conta correta. Um repositório privado pode aparecer como inexistente para quem não tem acesso.
  2. Confira git remote -v. O remoto deve usar o endereço HTTPS fornecido pelo repositório, sem senha nem token na URL. Confirme usuário, organização e nome do projeto antes de alterar qualquer endereço.
  3. Retome o fluxo HTTPS com GCM ou GitHub CLI. A senha da conta GitHub não autentica Git por HTTPS. No Linux com CLI, gh auth status ajuda a conferir a conta e a sessão.
  4. No Windows, uma conta antiga pode estar salva no Gerenciador de Credenciais. Siga a orientação oficial e remova apenas a entrada GitHub incorreta se necessário; a próxima operação pedirá novo login. Não limpe outras credenciais.

Se a organização exigir SSO ou outras políticas, peça orientação a quem administra o acesso. Nunca desative a verificação de certificado TLS para contornar um erro.

O convite da dupla ainda está pendente

Quem convidou deve conferir o nome de usuário e o estado do convite em Settings → Collaborators do repositório. Quem recebeu deve entrar na conta convidada e aceitar o convite recebido por e-mail ou pelo link de convite. Depois, reabra o repositório com essa conta.

Ter o link do projeto não concede permissão de escrita. Não publique dados reais nem altere a visibilidade para contornar o convite. Veja convites para colaboradores.

Push rejeitado: “non-fast-forward” ou “fetch first”

A dupla pode ter enviado commits que sua cópia ainda não tem. Combine quem está editando, confira a branch com git branch --show-current e execute git status. Se houver alterações locais, conclua e registre sua etapa antes de integrar; se não souber o que registrar, peça ajuda.

Com a árvore de trabalho limpa, e na branch compartilhada da atividade, busque e integre o remoto. O exemplo usa main; substitua pelo nome combinado se for outro:

git fetch origin
git log --oneline --graph --all -8
git merge origin/main
git status

Se o merge abrir um editor para a mensagem do commit, salve e feche para concluir. Se aparecer conflito, use a próxima seção. Depois de conferir o resultado e concluir a integração, tente git push origin main novamente. Fonte: push rejeitado por histórico divergente.

“Permission denied”, “protected branch” e regras de revisão são outros problemas: confira conta, convite e fluxo de pull request com a dupla. Não tente sobrescrever o histórico remoto.

Conflito: “CONFLICT” ou “unmerged paths”

  1. Execute git status e abra no editor os arquivos indicados.
  2. Encontre os marcadores <<<<<<<, ======= e >>>>>>>. Converse com a dupla, escolha ou combine o conteúdo final e remova os três marcadores.
  3. Salve e confira o arquivo, incluindo a página no navegador. Prepare apenas o arquivo resolvido, por exemplo git add index.html.
  4. Execute git status. Quando todos os conflitos estiverem resolvidos, conclua com git commit -m "Resolve conflito em dupla", confira o resultado e envie quando combinado.

Se quiser interromper a tentativa de merge, peça ajuda antes. git merge --abort tenta retornar ao estado anterior; se havia alterações sem commit antes do merge, a recuperação pode falhar. Preserve uma cópia dos arquivos importantes fora do repositório antes de qualquer recuperação. Não apague arquivos para fazer a mensagem sumir.
