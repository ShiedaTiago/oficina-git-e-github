Antes da oficina

Prepare seu ambiente

Escolha seu sistema. Você precisa de Git, um editor de texto e um navegador. Este guia abre sem internet; baixar programas e usar GitHub exige conexão. Os comandos são digitados por você no terminal, uma linha de cada vez.

1. Windows: instale e abra o Git Bash

  1. Baixe o instalador para sua arquitetura em Git para Windows. O projeto Git for Windows inclui Git Bash e Git Credential Manager.
  2. Execute o instalador. Mantenha Git Bash e Git Credential Manager disponíveis. Se houver escolha de editor, use um que você conheça; o Visual Studio Code é uma opção se já estiver instalado.
  3. Abra Git Bash pelo menu Iniciar. Esse será o terminal usado na oficina; os comandos compartilhados funcionam nele.
git --version

Resultado esperado: uma linha como git version 2.x.y.windows.z. Use Git 2.28 ou superior; o restante do número pode variar. Se o comando não existir, feche e reabra o Git Bash; veja o diagnóstico de instalação.

1. Linux: use o terminal da distribuição

Abra o aplicativo Terminal. Escolha apenas o grupo correspondente à sua distribuição. Os comandos de instalação precisam de internet e permissão de administrador; sudo pode pedir a senha do computador, sem mostrar caracteres enquanto você digita. Em uma máquina administrada, peça a instalação à equipe responsável.

Debian / Ubuntu / Mint

sudo apt update
sudo apt install git

Fedora

sudo dnf install git

Depois, em qualquer uma delas:

git --version

Espere uma linha como git version 2.x.y. Consulte a instalação oficial por distribuição para outros sistemas. Use Git 2.28 ou superior para os comandos da oficina, incluindo git init -b. Não é preciso ter a versão mais recente; se a distribuição fornecer uma versão anterior, peça ajuda para atualizar.

2. Saiba em qual pasta você está

Use Git Bash no Windows e Terminal no Linux. Não digite os símbolos de prompt, como $, nem as linhas de resultado. As aspas fazem parte do comando quando o caminho tem espaços.

pwd
ls
mkdir -p ~/oficina-git
cd ~/oficina-git
pwd

pwd mostra sua localização; ls lista arquivos; cd troca de pasta. ~ representa sua pasta pessoal. No Git Bash, C:\Users\Ana aparece como /c/Users/Ana. Para uma pasta com espaço, use, por exemplo, cd "/c/Users/Ana/Minha pasta".

Extraia o pacote da oficina e localize examples/site-da-turma. Faça uma cópia dessa pasta para ~/oficina-git/site-da-turma. Não inicialize Git na sua pasta pessoal inteira. O exercício explicará quando executar git init na cópia.

Em um editor de texto, confirme que consegue abrir e salvar index.html. Mantenha a extensão .html, sem acrescentar .txt.

3. Configure a autoria dos commits

O nome e o e-mail ficam registrados nos commits. Eles não são senha nem login. Primeiro, confira o que já existe:

git config --global user.name
git config --global user.email

Se estiver vazio ou incorreto, substitua os exemplos abaixo pela identidade que você quer registrar. Ana Exemplo e o endereço abaixo são fictícios. --global aplica a configuração aos seus repositórios nesse usuário do computador.

git config --global user.name "Ana Exemplo"
git config --global user.email "ana@example.com"

Para preservar seu e-mail pessoal, abra GitHub → foto do perfil → Settings → Emails, ative Keep my email addresses private e copie o endereço noreply exibido na sua conta. Use esse endereço exato em user.email; não invente um. Alterar a configuração afeta commits futuros. Fonte: e-mail de commits no GitHub.

Confira de novo com os dois comandos de consulta. Em computador compartilhado ou para manter outra identidade de trabalho, configure somente a cópia do exercício depois de git init: execute os mesmos comandos sem --global, dentro do repositório.

4. Prepare sua conta GitHub

Crie uma conta em github.com/signup, se necessário, e verifique o e-mail. Guarde seu nome de usuário para a atividade em dupla. Se a conta exigir autenticação de dois fatores, tenha acesso ao seu método de confirmação.

Preparar a conta é diferente de conectar o terminal. Este material não faz login, não coleta dados e não executa comandos. Você fará a autenticação na etapa de conexão ao GitHub, no seu próprio computador.

Conexão HTTPS: faça no momento da prática

GitHub recomenda Git Credential Manager ou GitHub CLI para HTTPS. A senha da sua conta não autentica operações Git por HTTPS.

  • Windows: use o Git Credential Manager incluído no Git for Windows. Ao fazer uma operação HTTPS que exige acesso, siga a janela do navegador e confirme a conta correta e o segundo fator, se solicitado.
  • Linux: instale o GitHub CLI seguindo o guia oficial para a distribuição. gh é um programa separado do Git. No terminal, execute o comando abaixo, escolha GitHub.com → HTTPS → autenticar Git: Yes → navegador e siga as instruções. O manual de gh auth login explica o fluxo.
gh auth login
gh auth status

No Linux, GCM também é alternativa, mas requer configuração de um armazenamento seguro. O GitHub CLI pode recorrer a um arquivo de texto se não houver armazenamento seguro disponível; confira o aviso do programa e peça ajuda em máquinas compartilhadas. Use uma sessão pessoal com armazenamento seguro.

Nunca coloque senha, token ou código de confirmação no HTML, README, URL do remoto ou commit. Não compartilhe a tela de credenciais. Se aparecer um pedido de senha no terminal, não tente a senha da conta: volte ao fluxo do gerenciador ou peça ajuda. Fonte: autenticação no GitHub.

Pronto para começar?

  • Git 2.28 ou superior responde a git --version.
  • Você reconhece seu terminal e sua pasta de trabalho.
  • Consegue editar o projeto inicial e conferiu nome/e-mail.
  • Tem uma conta GitHub verificada para a etapa em dupla.

Se algo falhar, abra o guia de diagnóstico. Você ainda pode acompanhar a apresentação e as simulações offline enquanto resolve o acesso.
